用户命盘档案管理

把「填一次出生信息」从一次性动作，变成可管理、可复用、可增长的用户资产。

项目：FateCipher 负责人：章青云 GitHub：1Yunn/FateCipher 产出日期：2026-09-09 状态：已上线 35074fc

为什么新增档案管理

在 v0.1 里发现的问题

#场景发生了什么
P0多账号串数据用户 A signIn 建档 → signOut → 用户 B signIn，B 看到 A 的档案。旧 key fatecipher.profile.bazi 是全局的，不管谁登录都写同一个 key
P0额度也串了AI 问答每日 5 次额度，旧 key fatecipher.ask.quota 也是全局。用户 A 用完了，换用户 B 登录显示"0 次"
P1四种玩法各填一次八字要填出生、紫微也要填、AI 问答想用个性化功能还得再建一次。同一用户，四份出生信息
P1不能编辑/删除填错了出生时间？没法改。想让 AI 换个侧重点？也没法设

一句话

v0.1 跑出了产品价值，但 用户数据没有"归属"——属于谁、用在哪、能不能改——全没有。档案管理就是给用户数据加归属。

用户故事

#用户故事验收要点
US-01作为已登录用户，我希望能保存一份命盘档案，这样四种玩法都能共用我的出生信息建档后，八字/紫微/AI问答三页都检测到"档案已保存 · 1997-08-15 · 申时"
US-02作为已登录用户，我希望 AI 问答能结合我的档案来回答，这样回答更有针对性有档案的用户问事业运，AI 回复里引用"你的命盘日主干支"；无档案用户看到紫色建档 CTA
US-03作为用户 A，我希望用户 B signIn 时看不到我的档案，这样我的隐私有保障A 的档案存在 fatecipher.profile.a@example.com，B 的存在 fatecipher.profile.b@example.com，key 隔离
US-04作为建档用户，我希望能编辑/删除我的档案，这样我对自己的数据有控制权/profile 页面三态：空态 → 详情 → 编辑，删除有二次确认弹窗

详细方案

M1 ProfileStore（src/lib/profile.ts）

API职责
getProfile(email)读 fatecipher.profile.{email}，不存在返回 null
saveProfile(email, data)写 fatecipher.profile.{email}，自动加 createdAt / lastUpdated
deleteProfile(email)删 fatecipher.profile.{email}
migrateFromLegacy(email)读旧 key → 搬 → 删旧 key。新 key 已存在则跳过
getQuota(email) / consumeQuota(email)额度按 email 分账

M2 /profile 档案管理页

AuthGuard 包裹（未登录跳 /login）。三态切换：

  • • 空态（无档案）：标题"还没有命盘档案" + 双 CTA（去八字测算 / 手动建档）
  • • 详情态（有档案）：标题"Yunn_ 命盘档案" + 字段展示 + 编辑/删除按钮
  • • 编辑态：新建表单（出生日期/性别/时辰/出生地），保存/取消按钮
  • • 删除确认：confirm 弹窗 → 二次确认 → 清除 localStorage → 回到空态

M3 消费方接入（4 个文件）

文件旧代码新代码
bazi-flow.tsxSTORAGE_KEY 常量ProfileStore.saveProfile(email, data)
ziwei-flow.tsx同上同上
ask-engine.ts硬编码读全局 keyloadAskContext(email?) 接受 email
ask-chat.tsx硬编码读额度 keyProfileStore.getQuota / consumeQuota(email)

异常与边界

#场景处理
E1旧 key 是坏 JSONtry-catch 包裹 migrate；搬失败不阻塞 signIn
E2编辑保存时另一标签页已改档案v0.2 直接覆盖；v0.3+ 加乐观锁
E3email 大小写所有 email 一律 .toLowerCase()
E4localStorage 已满try-catch；提示清理旧数据
E5未登录直接访问 /profileAuthGuard 跳 /login
E6手动输入 /profile URL（无档案）显示空态 + 建档 CTA
E7signIn 时旧 key 已被搬过（新 key 已存在）幂等：跳过迁移，不覆盖
