用户故事 & 核心场景

US-01 多账号建档隔离（P0）

USER STORY
作为 共用同一浏览器的 A 用户，我希望 我的命盘档案和 B 用户的互不干扰，这样 我 signOut 再 signIn 回来时，看到的还是我的盘。
  • A 建档 → signOut → B 不建档 → B signIn → B 进入 AI 问答时走通用开场（hasProfile: false）
  • B 建档 → signOut → A signIn → A 进入 AI 问答时承接 A 的档案
  • 切换账号不丢失各自的 AI 问答额度

US-02 独立档案管理（P0）

USER STORY
作为 已建档的老用户，我希望 在任何页面都能快速找到档案管理入口，这样 我想改时辰时不用重跑八字测算。
  • SiteHeader 已登录状态下有「我的档案」入口 → 直达 /profile
  • /profile 页面可查看档案详情、编辑任意字段、删除档案
  • 保存后 lastUpdated 自动刷新

US-03 未建档引导（P1）

USER STORY
作为 刚注册的新用户，我希望 AI 问答主动提醒我先建档，这样 我问的问题能被更精准地回答。
  • 未建档用户进入 AI 问答 → 开场下方显示「还没填命盘档案」引导条
  • 引导条有「去八字测算」和「手动建档」两个按钮
  • 建档成功后引导条自动消失

US-04 数据自动迁移（P0）

USER STORY
作为 v0.1 已建档的老用户，我希望 升级后我的档案自动出现在新版本，这样 我不用重新填一遍出生信息。
  • v0.2 第一次 signIn / signUp → 自动把旧 key fatecipher.profile.bazi 搬到 fatecipher.profile.{email}
  • 迁移幂等：signIn 多次不会重复搬迁
  • 迁移完成后删除旧 key，避免污染后续登录

需求背景

FateCipher v0.1 已有八字、塔罗、紫微、AI 问答四种命理玩法。四种玩法都需要基于用户出生信息（出生日期、性别、出生地、时辰）做个性化解读——这个数据就是「命盘档案」。

v0.1 里档案通过八字 / 紫微测算的引导流程写入 localStorage，key 为 fatecipher.profile.bazi，全局唯一，不带用户维度前缀。auth-context.tsx 独立维护着用户认证系统（fatecipher.users / fatecipher.currentUser），但档案与用户完全隔离——像是挂在浏览器上的一份公共便签。

优先级问题实际影响
P0多账号同一浏览器时档案串数据A 用户立了盘 → signOut → B signIn → 八字测算直接显示 A 的盘；AI 问答承接语也跟着错
P0没有独立的档案管理界面用户想把出生时辰从"子时"改成"丑时"，必须重跑一遍八字测算 3 步引导流程
P1AI 问答额度全局共享A 用了 5 次免费问答 → signOut → B signIn → B 一看额度也用完了

验收 Checklist

ProfileStore（单元测试已覆盖）

  • newProfile → saveProfile → getProfile 返回完整对象（含 createdAt）
  • updateProfile patch 后 lastUpdated 自动刷新
  • deleteProfile 后 getProfile 返回 null
  • migrateForUser：旧 key 存在 + 新 key 不存在 → 迁移成功，旧 key 删除
  • migrateForUser：新 key 已存在 → 跳过
  • migrateForUser：旧 key 不存在 → 跳过
  • consumeQuota：第一次返回 true，第 6 次返回 false
  • 额度跨天自动重置

多账号隔离（手动）

  • 用户 A（a@ex.com）signIn → 八字测算立盘 → signOut
  • 用户 B（b@ex.com）signIn → /profile → 显示空态，/ask → 通用开场 + CTA
  • 用户 B signOut → 用户 A signIn → /profile → 显示 A 的档案
  • 用户 A 用完 5 次额度 → 用户 B signIn → B 还有 5 次

UI 交互（手动）

  • SiteHeader 已登录下拉有「我的档案」→ 跳转 /profile
  • /profile 空态 → 点击「去八字测算」→ /fortune/bazi；点击「手动建档」→ 同页表单
  • /profile 详情 → 编辑字段 → 保存 → 回到详情，字段更新，lastUpdated 刷新
  • /profile 详情 → 删除 → confirm → 确认 → 回到空态
  • /profile 编辑表单 → 取消 → 不变
  • /ask 未建档 → 开场下方出现紫色 CTA 条
  • /ask 建档后 → CTA 条自动消失，承接语个性化

异常与边界

#场景处理策略
E1localStorage 不可用（隐私模式 / 禁用）ProfileStore 静默降级，档案页表单禁用提交并提示「当前环境无法保存档案」
E2编辑保存时另一标签页已改档案v0.2 直接覆盖（无多标签冲突检测），待 v0.3+ 加乐观锁
E3删除档案 → 确认弹窗 → 用户点取消关闭弹窗，不做任何操作
E4删除档案后立刻进入 AI 问答AI 问答走通用开场（hasProfile: false），CTA 引导建档重新出现
E5旧 key 数据格式异常（不是合法 JSON）迁移 catch 后静默跳过，不阻断 signIn 流程
E6未登录访问 /profileAuthGuard 拦截遮罩 + redirect=/profile，登录后自动回跳
E7email 大小写ProfileStore 内部 email.toLowerCase() 统一，key 不重复
