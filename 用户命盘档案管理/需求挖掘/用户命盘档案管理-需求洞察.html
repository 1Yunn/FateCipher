三、问题分类（按影响链）

P0数据隔离缺失

证据
localStorage key 全局 fatecipher.profile.bazi，未拼接 user.id / email 前缀
影响
同一浏览器切换账号，B 用户能看到 A 的出生时辰，且 AI 问答会基于 A 的盘面解读 B 的问题
修复成本
低：改 3 个常量 + 加迁移逻辑

P0没有档案管理界面

证据
SiteHeader 右侧只有「用户图标」下拉（登录/注册/退出）；已登录后下拉只有「命理体系 / AI 问答 / 退出登录」，无档案入口
影响
用户想改出生时辰（例如记错了）只能重新跑一遍八字测算；建档后无法确认存了什么；产品没有「我的档案」这个心智入口
修复成本
中：新增 /profile 页面 + 导航入口 + 读写逻辑

P1建档入口被动

证据
ask-engine.ts L235 只能文案引导「去八字测算」；塔罗测算页没有建档 CTA；AuthGuard 拦截后不提示建档
影响
AI 问答重复输出「你还没立命盘档案」通用开场，降低回答质量；塔罗用户流失（塔罗不需要出生时辰但体验不如有档案时连贯）
修复成本
中：需要设计主动建档场景和引导链路

P1档案只支持「生辰八字」一种模板

证据
STORAGE_KEY 叫 profile.bazi，结构里只有四柱相关字段；紫微复用同一份出生时间但没有紫微特有的辅助字段
影响
产品叫「命盘档案」实际是「八字档案」；未来若接入西方占星（本命星盘）需要新档案类型
修复成本
中：抽象成 profile template registry

P2档案生命周期无感知

现状
没有 lastUpdated、createdAt 时间戳；AI 问答不知道档案是 1 年前填的还是刚填的；没有「档案完整度」概念
影响
AI 无法提示「你的档案还缺出生地，补上后紫微排盘更准」

四、竞品参考（功能层面）

竞品档案管理方式亮点与 FateCipher 差异
神巴巴（shen85） 独立「我的命盘」页面，支持多个命盘（自己 + 家人） 家人档案、档案切换 FateCipher 暂不需要多人档案，但「独立档案页」模式可参考
测测（cecer123） 按测算类型分别建档，结果收藏与档案关联 档案 ↔ 历史结果双向跳转 FateCipher 暂无历史结果功能，可作为后续扩展
DeepSeek / Kimi 上传文件 / 对话中提取 → 长期记忆 「让 AI 记住我」主动心智 FateCipher 的命盘是结构化强数据，不是自由文本

五、机会点（按优先级）

必须做机会 1：数据隔离 + 用户维度 key

关联证据
  • 当前 localStorage key 全局共享
  • AuthProvider 已有 user.email
预期价值
  • 修复安全/隐私 bug
  • 为后续多档案类型和后端同步铺路
验证方法
  • 手动切换账号，检查各账号 AI 问答的开场承接是否对应各自档案
  • 本地写迁移脚本：旧 key → 新 key（如果新 key 不存在）

必须做机会 2：独立档案管理页 /profile

关联证据
  • 用户下拉菜单没有档案入口
  • ask-engine.ts 文案主动引导「去八字测算立个盘」
预期价值
  • 建立产品心智：FateCipher 有「我的档案」
  • 减少建档摩擦：3 分钟建档 vs 必须跑完 2 分钟八字仪式
  • 塔罗/紫微用户也能建档，扩大档案覆盖率
验证方法
  • 建档完成率：从「进入八字测算」到「档案写入成功」的漏斗
  • AI 问答承接质量：有档案用户的回答长度 / 追问次数

应该做机会 3：主动建档引导链路

场景
  • AI 问答欢迎语「施主请讲」→ 未建档用户 → CTA「先立个档案让回答更贴身」
  • AuthGuard 拦截遮罩 → 登录后 → 引导建档
  • 塔罗测算结果页 → 推荐「补个出生时辰，下次就能结合你的盘来解」
验证方法
  • 建档入口点击率（埋点）

可以做机会 4：档案完整度 + 智能补充提示

场景
  • 出生地缺失 → 提示「补上出生地，紫微排盘会更准」
  • 档案年龄 > 180 天 → 提示「你的档案是半年前填的，要不要确认一下？」

六、移交 PRD 的范围与约束

本期（v0.2）纳入 PRD 的范围

  • 用户维度 localStorage key 改造（含迁移）
  • /profile 档案管理页：查看、编辑（出生时间 / 性别 / 出生地）、删除
  • SiteHeader 用户下拉菜单新增「我的档案」入口（已登录可见）
  • AI 问答页：未建档用户的主动建档 CTA
  • AuthGuard 后的建档引导
  • 档案字段加 createdAt / lastUpdated 时间戳

暂不纳入

  • 家人档案（多个档案切换）—— 当前 v0.2 只有单档案
  • 档案历史版本 / 改档回溯
  • 命理工具偏好（比如「我只信紫微，不信塔罗」）
  • 西方占星本命星盘模板（profile 模板抽象层留接口，不实现）
  • 后端同步（当前 Auth 全部 localStorage mock，PRD 里注明「预留 async 接口」）
  • 历史结果收藏（测测那种模式）

关键约束

  • 不破坏现有八字 / 紫微的写入链路（它们仍是建档入口之一）
  • 不引入后端依赖（继续 localStorage），接口层抽象好 async 签名方便后续迁移
  • 迁移脚本幂等：跑多次不会重复搬数据或覆盖新数据
