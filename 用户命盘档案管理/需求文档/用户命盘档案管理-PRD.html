需求背景

FateCipher v0.1 已有八字、塔罗、紫微、AI 问答四种命理玩法。四种玩法都需要基于用户出生信息（出生日期、性别、出生地、时辰）做个性化解读——这个数据就是「命盘档案」。

v0.1 里档案通过八字 / 紫微测算的引导流程写入 localStorage，key 为 fatecipher.profile.bazi，全局唯一，不带用户维度前缀。auth-context.tsx 独立维护着用户认证系统（fatecipher.users / fatecipher.currentUser），但档案与用户完全隔离——像是挂在浏览器上的一份公共便签。

这导致三个实际问题：

优先级问题举例
P0多账号同一浏览器时档案串数据A 用户立了盘 → signOut → B 用户 signIn → 八字测算直接显示 A 的盘
P0没有独立的档案管理界面用户想把出生时辰从"子时"改成"丑时"，必须重跑一遍八字测算的 3 步引导流程
P1额度 key 全局共享A 用了 5 次 AI 问答 → signOut → B signIn → B 一看额度也用完了

详细方案

一级模块 二级功能 页面 / 触发时机 描述
M1
数据层
lib/profile.ts		 档案 Key 改造 + 迁移 AuthProvider signIn / signUp 成功后
【功能逻辑】用户登录时，检查旧 key fatecipher.profile.bazi 是否存在，新 key fatecipher.profile.{email} 是否不存在。两者同时满足时，把旧 key JSON 搬到新 key，加 migratedAt 标记。幂等：新 key 已存在时跳过。迁移完成后删除旧 key。
【边界说明】旧 key 不存在（新用户）→ 跳过；新 key 已存在（多账号已建档）→ 跳过；localStorage 不可用 → 静默降级不阻断启动。
档案 Schema 升级 写入时
【数据与内容规则】Profile 对象新增字段：createdAt（首次建档 ISO 时间）、lastUpdated（最后修改 ISO 时间）、migratedAt（迁移时间，仅迁移时出现）。
M2
档案管理页
/profile		 档案详情视图 /profile（已登录且有档案）
【页面元素】页面标题 + 用户名下的档案卡片：出生日期（大号思源宋体）、性别、时辰（或「时辰未知」）、出生地（或未填）、建档时间、上次更新时间。底部编辑 / 删除按钮。
【交互说明】进入页面时通过 ProfileStore 读取 fatecipher.profile.{email}。无档案时展示空态（见 M3）。
编辑档案表单 /profile 点击「编辑」→ 同页切换表单
【页面元素】出生日期（日期选择器，max=今日，min=1900-01-01）、性别（男/女 toggle）、时辰（子时~亥时 + 时辰未知）、出生地（文本输入，选填）。底部「保存」+「取消」。
【交互说明】点击编辑 → 卡片变表单，预填当前值。点击保存 → 写 localStorage + 更新 lastUpdated → 回到详情视图。点击取消 → 不变。
M3
空态与引导		 未建档引导 CTA /profile（无档案）
/ask（无档案）
【/profile 空态】Card 内图标 + 大标题「还没有命盘档案」+ 副文。主按钮「去八字测算」→ /fortune/bazi，次按钮「手动建档」→ 同页表单。
【/ask CTA】AI 问答开场消息下方出现浅紫色提示条：「还没填命盘档案 · 填一次出生信息，AI 会结合你的四柱来答」+ 两个跳转按钮。建档后自动消失。
M4
导航入口		 SiteHeader 用户下拉 已登录状态下 SiteHeader 右侧触发
【桌面端】用户头像下拉：用户信息 → 分隔线 → 「我的档案」（→ /profile）→ 分隔线 → 「退出登录」。
【移动端】汉堡菜单内保持相同结构。
M5
消费方接入		 bazi-flow / ziwei-flow / ask-engine / ask-chat 八字测算页、紫微测算页、AI 问答页
【改造内容】所有 fatecipher.profile.bazi 直读写替换为 ProfileStore.getProfile/setProfile(user.email)。AI 问答额度 fatecipher.ask.quota 改为 ProfileStore 内部管理（consumeQuota(email) / getQuota(email)）。

异常与边界

#场景处理
E1localStorage 不可用（隐私模式 / 禁用）ProfileStore 静默降级，档案页表单禁用提交按钮并提示「当前环境无法保存档案」
E2编辑保存时另一标签页已改档案v0.2 直接覆盖（无多标签冲突检测），后续版本加乐观锁
E3删除档案 → 确认弹窗 → 用户点取消关闭弹窗，不做任何操作
E4删除档案后立刻进入 AI 问答AI 问答走通用开场（hasProfile: false），CTA 引导建档重新出现
E5旧 key 数据格式异常（不是合法 JSON）迁移 catch 后静默跳过，不阻断 signIn 流程
E6多用户共用浏览器，其中一人旧 key 未迁移迁移只在当前登录用户有新 key 需求时触发，不影响其他用户的旧 key
E7未登录用户访问 /profileAuthGuard 拦截遮罩 + redirect=/profile，登录后自动回跳
